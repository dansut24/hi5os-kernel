# HTTPS integration gate
v0.1.6 implements a fixed 2 MiB GlobalAlloc-compatible heap (direct allocation self-tests, no alloc crate yet), UEFI GetTime snapshot before firmware exit with validated calendar conversion and VM UTC assumption when zone is unspecified, and CPUID-gated RDSEED/RDRAND with bounded retries and explicit unavailable status. Clock is not authenticated, may drift, and is not yet a TLS time provider. No hardware RNG means no entropy; never use timer/constant fallback. CPU/hypervisor entropy trust is an assumption; no firmware RNG or software DRBG yet. No secrets in logs. No TLS library linked or certificate validation. Rustls 0.23 remains evaluation candidate: pin a compatible no_std allocator, provider, trust roots, time provider, general reliable TCP byte stream, audit licensing and test valid certificate, wrong hostname, unknown CA, expiry, bad signatures, no entropy/time. No bypass/downgrade. References https://docs.rs/rustls/latest/rustls/crypto/struct.CryptoProvider.html and https://docs.rs/rustls/latest/rustls/client/struct.ClientConfig.html.
