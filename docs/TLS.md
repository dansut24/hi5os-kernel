# HTTPS integration gate
Rustls 0.23 is the preferred candidate to evaluate (not yet linked). no_std requires an allocator, compatible CryptoProvider and TimeProvider; reference https://docs.rs/rustls/latest/rustls/client/struct.ClientConfig.html and https://docs.rs/rustls/latest/rustls/crypto/struct.CryptoProvider.html. Embedded TLS alternatives require independent review of certificate-chain and hostname checks on the exact target. Current UEFI target, Rust 1.85.1 and firmware handoff must be verified with a pinned dependency set, licensing audit and CI. Implement kernel heap, secure randomness with supported hardware or reviewed entropy source (no timer-derived RNG), trusted UTC and root store, general TCP byte-stream with retransmission/closure, and a bounded TLS client. CI must test trusted valid certificate, wrong hostname, unknown CA, expired cert and bad signature; no insecure bypass or HTTP fallback for HTTPS. No HTTPS functionality claimed in v0.1.5. Keep EXE/MSI untrusted and non-executable until isolated loader and integrity verification.
