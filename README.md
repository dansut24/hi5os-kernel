# Hi5OS v0.2.1 — consolidated 7-Zip startup probe
Stable v0.2.0 bd17e15 qualified full CI and user manual. Candidate introduces separately mapped ring3 trial, NX page permissions, guarded stack, bounded PIT watchdog, recoverable selected CPU exceptions, saved registers/FX state, SHA256 exact official 7za.exe pin derived from verified archive, real entry-point attempt and static IAT stubs. Unsupported APIs stop and report exact DLL/symbol, not fabricated success. Narrow runtime includes selected kernel32 calls, malloc/free, memcpy/memmove/memset/memcmp/strlen, __set_app_type, limited __getmainargs, stdout. Incomplete CRT, no constructor runner, file/directory operations or installer; no full process isolation, exception unwinding or security guarantee. Test uses isolated CI guest and only original pinned binary, no redistribution. winfault checks UD2 and infinite loop recovery; 7za -h only with verified current download. Help qualification explicitly requires actual captured 7-Zip usage output and exit zero; diagnostic CI may pass on contained unsupported API/fault/timeout without help. Existing data unchanged. No production/EU changes.
Additional consolidated work: bounded private RAM filesystem with directory create/remove, file open/create/read/write/seek/size/truncate/delete/attributes, access/share checks, normalized path rejection, no real-disk writes; Win32 API adapters, CRT realloc/strcmp/wcscmp, limited stream functions and user-mode _initterm constructor loop. RAMFS self-test required by winfault/7-Zip CI. Not persistent or a complete Windows filesystem; installer remains blocked. CRT stream layout and API behavior are limited prototypes, not full compatibility. Actual help still needs qualification.
