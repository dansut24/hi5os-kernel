# Hi5OS v0.1.2 — networking and download preview
Qualified v0.1.1 e618d62 (CI and user manual confirmation). baseline/v0.1.1 retained.
Candidate: polled Intel E1000 (PCI 8086:100e), static 10.0.2.15 on QEMU user network, ARP, limited single-connection IPv4/TCP and bounded HTTP/1.0 GET, native Hi5Browser numeric URL entry and plain-text/binary preview. Restricted to numeric 10.0.2.x destinations. No DNS/DHCP/TLS, HTML layout, JS, general browsing, robust TCP retransmission/congestion handling or public internet. Explicit fetch only; no network on boot. F8 or 6 opens browser, Ctrl+L clears URL, Enter/Go retrieves, F9 saves binary (max 4096 bytes) to dedicated data image in separate checksummed banks, not a general filesystem. EXE/compound format classification only, never executes downloaded data. No opening saved download in loader yet. Existing document slots unchanged. No production or EU changes. Only isolated test VMs, no physical drives or confidential data.
CI: legacy boot and document tests plus real guest Ethernet/ARP/TCP/HTTP via restricted SLIRP guestfwd to local HTTP server; verifies exact synthetic PE fixture on disk. UTM: duplicate stopped v0.1.1 VM, replace system image only, keep data disk, Q35 UEFI PS/2 enabled USB disabled. For network lab add Intel E1000 using Emulated VLAN/user mode if available, isolated fixture is CI-specific; default browser URL only works where a corresponding lab server is configured. Do not use bridged networking or public downloads. Candidate pending CI/manual.
Next: DHCP/DNS, TLS with trusted roots, full TCP stack, general binary filesystem, process isolation, PE loader/imports/Win32 and MSI engine; Hi5Office native document/spreadsheet development in parallel.
